# MP3 → TXT 本地转写工具技术方案

## 目标

用户双击一个启动入口，在浏览器中选择 MP3，获得可编辑、可复制、可下载的纯文本转写结果。

## 非目标

- 不生成 SRT、VTT、时间戳或说话人分离结果。
- 不支持批量任务、在线云转写、用户账户或多人协作。
- 不把 GPU 作为必要条件；默认优先保证普通 Windows 电脑可运行。
- 不在首版支持 MP3 以外的上传格式。

## 用户路径

1. 双击 `launcher/启动.bat`。
2. 首次点击「初始化 / 修复」，之后点击「启动 / 重启服务」和「打开转写页面」。
3. 选择或拖入 MP3，点击「开始转写」。
4. 查看进度，编辑或复制文本，点击「下载 TXT」得到 `原文件名.txt`。

## 架构

`图形启动器 + Web 页面 → 配置/初始化/任务编排 → faster-whisper → 浏览器文本区 + 本地 TXT`

| 层 | 当前实现 | 职责 | 替换边界 |
|---|---|---|---|
| 用户入口层 | Tkinter 启动器、原生 HTML/CSS/JavaScript | 初始化、启动、状态展示、上传、进度、编辑与下载 | 更换 UI 时保留本地 HTTP API，不改模型 |
| 编排/胶水层 | Python 配置脚本、Flask 服务、后台任务队列 | 路径解析、依赖安装、模型准备、单任务串行调度、错误转换、临时文件清理 | 更换引擎时主要改转写适配与冒烟测试 |
| 外部引擎层 | faster-whisper / CTranslate2 | 本地加载 small 模型，输出分段文本 | 模型名称、下载仓库、设备与计算精度均来自配置 |
| 最终消费端 | 浏览器与 `data/output` | 页面编辑、复制、下载；本地保存服务生成的 TXT | 更换阅读器不影响转写过程 |

### 关键取舍

- 采用元宝方案中的 `faster-whisper`、中文识别、VAD 过滤和逐段写文本思路；去掉命令行入口和时间戳，并补齐 Web、进度、配置及运维能力。
- 默认 `cpu + int8`，避免无 NVIDIA 显卡或 CUDA 组件时初始化失败。有合适显卡时可只改本机配置。
- 使用单 worker 串行执行转写，避免多个任务同时加载模型导致内存不足。
- 直接依赖为 `faster-whisper` 和 `Flask`，并显式锁定与其解码调用兼容的 PyAV；启动器、配置生成和测试使用标准库。
- 页面下载基于当前文本框内容生成 Blob，因此用户编辑后的内容也会进入下载文件。

## 配置模型

- 公共默认：`config/stack.yaml`。记录相对依赖根、版本、模型、服务、识别参数与资源要求。
- 机器私有：`config/stack.local.yaml`。只覆盖本机运行方式、私有路径或设备选择，已被 Git 忽略。
- 示例：`config/stack.local.yaml.example`，不包含真实机器信息。
- 生成物：`config/_env.json`。由 `scripts/apply_config.py` 合并并解析路径后生成，头部带 `_notice` 自动生成标记，禁止手改，不入库。
- 所有脚本从公共配置和本机覆盖读取值。代码不保存开发机绝对路径、用户名或另一套端口/模型默认值。

配置文件采用 JSON 兼容的 YAML 语法，使初始化尚未安装第三方包时也能由 Python 标准库读取。本机覆盖文件也必须保持合法 JSON 语法。

路径规则：

- `dep_root` 相对项目根解析，默认位于项目同级的 `voice2txt-deps`，不参与 Git。
- `paths.*` 相对 `dep_root` 解析，运行时和模型可以整体迁移。
- `data.*` 相对项目根解析，输入、输出与日志都被 Git 忽略。
- 生成配置前备份已有本机配置；重复生成结果一致。

## 初始化

1. 检查 Windows、Python、可用内存和磁盘；默认需要预留配置中声明的空间。
2. 通过 Python 启动器发现兼容解释器并优先选择 3.12，包括由 uv 安装且已注册到启动器的运行时；不使用开发机路径。
3. 在项目同级依赖目录的临时目录创建虚拟环境，校验解释器后切换；已有有效环境则复用。
4. 通过 PyPI 官方源安装锁定版本，失败后使用镜像；已有匹配版本跳过。
5. 从 Hugging Face 官方源下载 `small` 模型，失败后使用镜像；先下载到临时目录，校验必要文件后再移动。
6. 生成 `_env.json`，启动本地服务并执行健康检查。
7. 运行真实引擎冒烟：生成短音频，完成一次推理，验证可读取的 UTF-8 结果和任务元数据。
8. 失败时保留旧模型和旧运行环境；未完成的环境目录会重建，模型临时目录保留供下次续传但不会作为正式模型。用户可在启动器点击「初始化 / 修复」重试。

首次下载包含 Python 包与 small 模型，实际体积以安装源为准；模型通常约数百 MB，另需为依赖和缓存预留空间。下载只发生在初始化/修复或明确升级时，日常转写可离线运行。

## 升级与兼容性

- Python 包：读到新版本后，在 `upgrades` 下创建独立环境，安装、生成配置、启动并冒烟，通过后才切本机配置。
- 模型：下载到独立目录；验证必要文件和实际推理后切换。更大模型可能显著增加内存和耗时，不承诺效果更好。
- 用户 TXT、音频、本机配置和缓存不是“升级对象”，只能备份、迁移或清理。
- 跨引擎或跨大版本升级不称为无痛升级；必须检查 API、模型格式、设备支持和资源变化。
- 回滚时恢复升级前的 `stack.local.yaml` 备份，重新生成配置，启动旧环境并再次冒烟。

## 验收路径

- 新机器：按 `initProject.md` 从空依赖目录完成初始化、服务启动和真实引擎冒烟。
- 用户走查：只通过启动器和页面完成一次 MP3 → 可编辑文本 → `原文件名.txt`。
- 自动测试：配置合并、路径推导、MP3 校验、任务状态、纯文本输出和错误处理。
- 新路径模拟：复制项目到不同目录后重新生成配置，所有路径随项目根变化。
- 升级演练：独立目录准备 → 切配置 → 验证 → 恢复备份并验证。
- 硬编码审计：扫描代码中的盘符、用户目录和绕过配置的地址。
- 隐私审计：`git status --short`、`git add -A -n`、`git ls-files` 不包含音频、模型、运行环境、输出、日志、生成配置或本机私有配置。
