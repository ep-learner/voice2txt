# MP3 → TXT 本地转写工具架构说明

## 一句话

启动器把本地服务准备好，浏览器把 MP3 交给本机的 faster-whisper，识别出的纯文本再回到浏览器和本机 TXT 文件中。

## 一次完整操作背后发生了什么

1. 双击 `launcher/启动.bat` 后，图形窗口检查运行环境、模型和服务状态。
2. 首次点击「初始化 / 修复」时，程序准备 Python 环境和识别模型。这一步需要联网，之后可以离线转写。
3. 点击「打开转写页面」后，浏览器连接的是本机回环地址，不是互联网网站。
4. 选择 MP3 并点击「开始转写」，页面将文件发送到同一台电脑上的本地服务。
5. 服务按顺序处理任务。模型第一次加载时等待会稍长；识别期间，页面根据音频已处理比例显示进度、已耗时和估算剩余时间。
6. 引擎逐段返回文字，程序只保留文本内容，不保存或展示时间戳。
7. 完成后，文本出现在可编辑文本框，同时保存到本机输出目录。点击「下载 TXT」会下载当前文本框中的内容，所以手动修改也会保留。

## 三层各自负责什么

| 层 | 负责什么 | 用户需要知道什么 |
|---|---|---|
| 入口 | 启动器按钮、页面按钮、状态和容易理解的错误提示 | 日常只操作这一层 |
| 胶水层 | 找到依赖、读取配置、调用模型、排队、清理临时上传、把错误翻译成人话 | 不需要了解内部命令 |
| 外部引擎与消费端 | faster-whisper 负责识别；浏览器负责展示、编辑与下载 | 可以更换，但要验证兼容性 |

## 数据在哪里

- 运行环境、模型和下载缓存：项目同级依赖目录，由 `dep_root` 决定，默认是 `voice2txt-deps`。
- 临时上传：项目内 `data/input`。每个任务使用随机内部文件名，完成后自动删除；不会覆盖同名音频。
- 服务生成的 TXT：项目内 `data/output`，命名为 `原文件名.txt`，同名新结果会覆盖旧结果。
- 浏览器另下载的 TXT：由浏览器的下载设置决定。
- 本机私有配置：`config/stack.local.yaml`。
- 日志：项目内 `data/logs`，便于启动器显示错误位置。

依赖目录、音频、TXT、本机配置、生成配置、缓存和日志都不会进入 Git。转写时音频只在本机浏览器和本机服务之间传输，不会发送给在线识别服务。只有安装依赖和下载模型时需要访问对应下载站。

## 什么能换，换后有什么影响

| 对象 | 能否替换 | 主要影响 |
|---|---|---|
| 识别模型 | 可以 | 修改模型仓库和模型目录；需重新下载并验证，占用、速度和效果会变化 |
| CPU / GPU | 可以 | 修改本机设备与精度配置；GPU 还需兼容驱动和运行库 |
| faster-whisper | 可以 | 主要适配引擎调用和参数，完成实际识别冒烟后才切换 |
| 浏览器页面 | 可以 | 只要沿用本地任务 API，就不影响模型和已有 TXT |
| 启动器 | 可以 | 不影响识别结果，但要保留初始化、状态和修复能力 |
| 已有 TXT | 不是软件升级对象 | 直接备份或迁移，不需要重新识别 |

换模型不需要“训练”，但需要重新下载模型并做首次加载。换引擎可能改变识别参数和模型格式，不能只改一个名称就视为完成。

## 常见失败点在哪一层

| 用户看到的现象 | 可能层级 | 通常原因 |
|---|---|---|
| 启动器提示环境未就绪 | 入口/胶水层 | Python 不可用、依赖未装、磁盘不足或下载未完成 |
| 服务不在线 | 胶水层 | 服务未启动、配置端口被其他程序占用、运行环境损坏 |
| 一直提示准备模型 | 外部引擎层 | 首次下载/加载模型，或模型目录不完整 |
| 上传后立即报错 | 入口层 | 文件不是 MP3、文件过大或浏览器请求被中断 |
| 转写到一半失败 | 外部引擎层 | 文件损坏、内存不足、设备配置不适用 |
| 识别文字不准确 | 外部引擎层/素材 | 背景噪声、口音、音量、多人重叠或模型能力限制 |
| 下载内容不是页面修改后的文字 | 消费端 | 使用了旧下载结果；应再次点击当前页面的「下载 TXT」 |

## 升级是否值得

如果只是日常转写正常，没有必要追求每次更新。需要修复兼容问题、安全更新或明确改善识别体验时再升级。更大的模型不等于在当前素材上一定更好，却会占用更多磁盘和内存，并可能延长等待。已有 TXT 与模型相互独立，升级软件不会改动旧文本。
